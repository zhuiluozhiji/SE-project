# 软件工程测试报告写作提纲

## 1. 文档目的

本文件用于统一《校园学术活动智能推荐平台》测试报告的写作结构、章节内容和后续测试实现方向。

它承担两类作用：

1. 作为最终《软件工程测试报告》的写作提纲，规定每一章应写什么、如何写、引用哪些证据。
2. 作为后续测试用例设计与测试代码编写的展开依据，使自动化测试、手工测试和最终报告保持同一套结构。

本提纲遵循两条原则：

1. 保留课程给定测试报告模板的 `1-10` 章主结构，不推翻原有目录架构。
2. 结合本项目当前真实实现进行适配，补充前后端分离项目所必需的接口测试、联调测试、OCR/爬虫测试和覆盖说明。

## 2. 写作总原则

### 2.1 事实来源

报告中的测试结论必须优先基于以下事实来源撰写：

- 当前项目代码实现
- 当前接口规范文档
- 当前自动化测试脚本
- 实际执行的手工联调记录
- 实际执行的压力测试或稳定性测试记录

原则上不再使用早期“骨架阶段”文档中的推测性描述作为测试结论依据。

### 2.2 统一写法

除引言、概要、分析摘要外，测试相关章节统一按下列逻辑书写：

1. 说明本节测试对象和测试目的。
2. 给出测试内容或测试点列表。
3. 说明测试输入、前置条件、操作方式。
4. 给出预期结果。
5. 记录实际结果。
6. 给出结论，并说明是否通过、存在何种限制。

### 2.3 统一证据类型

后续写报告时，每一节优先引用以下证据：

- 自动化测试脚本与断言
- 接口返回结果截图或摘要
- 数据库变化前后对比
- 页面交互截图
- 日志、导出文件、OCR 识别结果

## 5 边界测试

> 本章围绕“极端输入、非法输入、权限异常、文件异常、时间规则异常”展开。后续测试用例编号建议与第 4 章模块保持对应。

### 5.1 登录注册与权限边界测试

应写内容：

- 错误密码

- 重复用户名
- token 缺失
- token 非法
- 普通用户访问管理员接口

### 5.2 活动检索与筛选边界测试

应写内容：

- 不存在的活动 ID
- 无结果筛选

### 5.3 课表导入边界测试

应写内容：

- 空文件
- 错误表头
- 旧版 `.xls`
- 重复课程
- 数据库中已存在同课程时段
- 节次非法
- 周次格式边界

### 5.4 日程与冲突检测边界测试

应写内容：

- 活动与课程冲突但未强制加入
- `force_add=true` 强制加入
- 删除单次课程实例
- 单双周、春夏学期、默认 16 周展开边界
- 非法日期格式

### 5.5 OCR 识别边界测试

应写内容：

- 截图超过 5 张
- 仅识别到开始时间
- 文本碎片化或竖排文本
- 图片无法识别

### 5.6 后台与爬虫边界测试

应写内容：

- 不存在的活动下架/编辑
- 爬虫无结果
- 爬虫运行失败
- OCR 接口文件缺失

## 6. 本提纲的使用方式

实际写作时建议采用以下流程：

1. 先按本提纲补齐 `docs/test-cases.md`，形成与第 4、5 章一致的用例编号。
2. 再按本提纲组织自动化测试脚本，保证脚本与报告章节可映射。
3. 执行自动化测试和手工测试，收集证据。
4. 最后按本提纲填写正式测试报告。

这样可以保证：

- 报告目录、测试用例、测试代码三者一一对应；
- 不会出现报告章节与实际测试内容脱节；
- 后续新增测试时也能直接知道应放入哪一章、哪一类证据中。
