# 项目当前总进度

更新时间：2026-05-23 CST  
维护人：组长  
当前阶段：工程骨架完成，团队统一切换到 Docker Compose 开发环境，核心业务功能仍在逐步实现。

## 1. 当前有效结论

本项目当前已经明确以下协作基线：

- 开发环境统一使用 Docker Compose。
- 所有组员统一通过 `mysql + backend + frontend` 三个服务进行开发、联调和测试。
- 不再把本地 `venv`、本地 `pip install`、本地 `uvicorn`、本地 `npm run dev`、本地 MySQL 作为团队标准流程。
- 文档、测试、接口规范仍然按照现有目录继续维护。

团队统一启动命令：

```bash
cp .env.example .env
docker compose up --build
```

团队统一测试命令：

```bash
docker compose exec backend pytest
```

## 5. 当前团队环境规范

### 5.1 启动环境

```bash
docker compose up --build
```

### 5.2 后台启动

```bash
docker compose up --build -d
```

### 5.3 停止环境

```bash
docker compose down
```

### 5.4 重置数据库

```bash
docker compose down -v
docker compose up --build
```

### 5.5 进入容器

```bash
docker compose exec backend sh
docker compose exec frontend sh
```

### 5.6 查看日志

```bash
docker compose logs -f mysql
docker compose logs -f backend
docker compose logs -f frontend
```

## 6. 当前协作要求

1. 不要提交 `.env`、`.venv/`、`node_modules/`、`frontend/dist/`。
2. 不要混用 Docker 和本地 Python/Node/MySQL 环境作为团队标准流程。
3. 接口字段变化后，必须同步更新 `docs/api-contract.md` 和相关前端 API 文件。
4. 数据库字段变化后，必须同步更新 `database/schema.sql` 和 ORM 模型。
5. 提交前至少执行一次 `docker compose exec backend pytest`。
6. 新同学接手开发时，以 `README.md` 当前环境配置说明为准，不再参考旧的本地 `venv` 启动流程。
