## 7. 交互状态覆盖

每个需要异步数据的页面均覆盖了四种状态：

| 状态 | 触发条件 | UI 表现 |
|------|----------|---------|
| 加载中 | API 请求进行中 | 骨架屏（首页）/ v-loading（列表、详情、日历）/ 按钮 loading 禁用（提交类操作） |
| 成功 | API 返回正常数据 | 正常渲染页面内容 |
| 空数据 | 接口返回空数组 | 提示文字（如"暂无活动，试试调整筛选条件"） |
| 错误 | 网络异常/超时/业务错误码 | ElMessage 错误提示（http 拦截器统一处理）+ 页面错误面板 + 重试按钮 |

## 8. 用户主流程连通性

以下主流程从前端侧已全部走通：

```text
[登录]  LoginView → 输入用户名密码 → auth.login() → 存 token → 跳转首页
   ↓
[浏览]  HomeView → 推荐活动卡片 → 点击查看详情
   ↓                    ↓
[筛选]  ActivityListView → 关键词/校区/类别/排序 → 分页翻页
   ↓
[详情]  ActivityDetailView → 查看信息 → 检测冲突 → 弹窗展示冲突
   ↓                                              ↓
[日程]  点击「加入日程」→ addActivityToSchedule() → "已加入日程"
   ↓
[日历]  CalendarView → 周视图展示课程+活动 → 不同颜色区分 → 导出 ICS
   ↓
[课表]  CourseImportView → CSV/Excel 上传解析 → 手动录入 → 确认导入
   ↓
[管理]  AdminView → 新增/编辑活动 → 下架确认 → 触发爬虫
   ↓
[个人]  ProfileView → 查看用户信息 → 兴趣标签 → 学术轨迹
```

## 10. 上游依赖

前端代码本身已完成，但页面实际数据取决于后端接口返回。需要后端同学确保以下接口返回格式一致：

| 后端负责人 | 需对齐的接口 | 前端期望返回格式 |
|------------|-------------|-----------------|
| mxy | `POST /auth/login` | `{ code: 0, data: { token: "...", user: { username, college, ... } } }` |
| mxy | `GET /users/me` | `{ code: 0, data: { username, college, major, tags: [...], ... } }` |
| mxy | `GET/POST/PUT/DELETE /admin/activities/*` | 标准 CRUD，活动对象含 id, title, status 等 |
| pxl | `GET /activities` | `{ code: 0, data: { items: [...], total: N } }`，items 含 id, title, campus, location, start_time, status, tags, description |
| pxl | `GET /recommendations/activities` | `{ code: 0, data: { items: [...], total: N } }`，item 含 id, title, reason, start_time, campus, location |
| lyy | `GET /schedules` | `{ code: 0, data: { events: [...] } }`，event 含 title, type/color_type, start_time, location |
| lyy | `POST /schedules/check-conflict` | `{ code: 0, data: { conflicts: [...] } }` |
| lyy | `POST /schedules/add-activity` | `{ code: 0, message: "success" }` |
| lyy | `GET /schedules/export-ics` | 返回 ICS 文件流（blob） |
| lyy | `POST /courses/import` | `{ code: 0, data: { courses: [...] } }`，course 含 course_name, teacher, weekday, start_section, end_section, location |

## 11. 适配说明

- **响应式**：所有页面在 960px 断点以下切换为单列布局，侧边栏保持 232px 固定宽度
- **容器化**：Vite 配置了 `watch.usePolling` 通过环境变量 `CHOKIDAR_USEPOLLING` 控制，Docker 环境下开启以支持文件监听
- **API 代理**：Vite dev server 将 `/api` 请求代理到 `VITE_DEV_PROXY_TARGET`（Docker 环境下为 `http://backend:8000`，本地开发为 `http://localhost:8000`）
